# GPU 電力リミットと推論速度・電力効率(2026-10-power-limit)

RTX 4080 SUPER の電力リミット(150 / 220 / 320 W)を変えたとき、Qwen3.6-35B-A3B(IQ3_XXS、フル GPU)の prefill / decode 速度と tok/s/W、そして MTP 投機デコードの利得と電力差がどう変わるかを測る。[2026-10-speculative-decoding](../2026-10-speculative-decoding/README.md) が 220 W 制限下で得た所見の追試。

## 結論

1. **「MTP は速くて低電力」は 220 W 制限の産物ではない。** 320 W でも mtp2 は none より平均電力が低く(要約 215 W vs 221 W、長文 288 W vs 305 W)、decode 比も同じ(要約 1.45、思考 1.57)。むしろ**電力を絞るほど長文 decode での MTP の利得が増える**: 長文 tool_use(56〜109k)で 320 W 1.09 倍 → 220 W 1.15 倍 → **150 W 1.63 倍**。150 W の mtp2(106 tok/s)は 220 W の none(96 tok/s)より速い
2. **短い decode は電力に鈍感、prefill と長文 decode は敏感。** 要約・思考の decode は 150 W で −6%、320 W で +0.5%(帯域律速。220 W で既に上限)。prefill は 150 W で −28〜36%、320 W で +6〜18%(演算律速)。長文 decode(attention が 100k ctx を舐める)は中間で −31% / +5%
3. **電力効率の最適点は 150 W。** decode tok/s/W は none で 0.98〜1.0(220 W の 1.4 倍)、mtp2 で 1.4〜1.5。prefill tok/s/W も 150〜220 W が最良(18.7 → 17.9 → 17.6)。320 W は長文 prefill +18% を電力 +43% で買う
4. **用途別の推奨**: チャット・要約・思考(短い prompt、decode 主体)なら **150 W + MTP** で 220 W の none の 1.3〜1.4 倍速く、電力は 2/3。Claude Code のような長文 prefill 主体なら 220 W が妥協点、320 W は prefill がどうしても欲しいときだけ
5. **SM クロックが律速の正体。** 長文 prefill 中のクロックは 150 W 1,326 MHz / 220 W 2,158 / 320 W 2,591(最大 3,105)。短い decode では 2,200〜2,730 MHz で、電力制限に関係なく帯域待ちになる

## なぜそうなるか

- **decode は 1 トークンごとに重み全体(IQ3_XXS 約 13 GB)を読む帯域律速。** メモリ帯域は電力制限で落ちない(クロック低下は演算側)ので、短い ctx の decode は 150 W でもほぼ同じ速度が出る。電力を増やしても速くならない
- **prefill と長 ctx の attention は演算律速。** 電力制限は SM クロックを下げるので、そのまま速度に出る
- **MTP は「1 回の重み読み出しで 2〜3 トークン」にする。** 長文 decode では attention(演算)の比率が高く、電力を絞ると none の 1 ステップが遅くなる一方、MTP は同じ 1 ステップで複数トークンを確定させるため、利得が電力不足を埋める方向に働く

mtp2 / none の比(同ブロック・同プロンプトで対にした平均):

| リミット | W1 長文  | W3 要約 | W4 思考 |
| -------- | -------- | ------- | ------- |
| 150 W    | **1.63** | 1.40    | 1.52    |

- 短い prompt(W3 / W4)では 320 W でも平均電力が 215〜221 W に留まり、リミットに当たらない。decode は電力を使い切れない(帯域待ち)
- 長文(W1)では 320 W のリミットに張り付く(305 W)。prefill +18% の代わりに電力 +43%
- mtp2 の prefill は none より 7〜22% 遅い(draft context の分)。どのリミットでも同じ傾向
- 受理率は電力に依存しない(W1 0.73 / W3 0.77 / W4 0.89 が 3 水準で一致)。決定的な greedy なので当然だが、計測の健全性の確認になる

## 次

- 150 W × MTP をチャット用の常用設定にするか(open-webui 経由の体感)。Claude Code 用は 220 W 据え置き
- 100 W / 120 W の下限側(`power.min_limit` は 150 W なので nvidia-smi では不可。クロック固定 `-lgc` で代替)
