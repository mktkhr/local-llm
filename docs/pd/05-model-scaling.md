# PD分離 PoC — モデルサイズによる損益分岐の変化

「PD分離の優位はモデルが大きいほど広がる」という仮説を、**転送コストをほぼ固定したまま計算コストだけを変える**設計で検証した記録です。

- 実施日: 2026-08-30
- 対象: Qwen3-4B-Instruct-2507 / Qwen3-8B / Qwen3-14B (すべて Q4_K_M)
- 結果: **仮説どおり。16k で 8.94x → 12.66x → 19.69x**

## 1. 実験設計

Qwen3-8B は Qwen3-4B-Instruct-2507 と **KV キャッシュのサイズが完全に一致します。**

Qwen3 系は GQA を採用しており、**モデルサイズが変わってもアテンション構成がほとんど変わりません。**

| | Qwen3-4B-Instruct-2507 | Qwen3-8B | Qwen3-14B |
| --- | --- | --- | --- |
| `n_layer` | 36 | 36 | 40 |
| KV ヘッド数 | 8 | 8 | 8 |
| `head_dim` | 128 | 128 | 128 |
| `n_embd_k_gqa` | 1024 | 1024 | 1024 |
| **KV (q8_0)** | **76.5 KiB/token** | **76.5 KiB/token** | **85.0 KiB/token** |
| 重み (Q4_K_M) | 2.50 GB | 5.03 GB | 9.00 GB |
| 重みの倍率 | 1.00x | 2.01x | **3.60x** |
| KV の倍率 | 1.00x | **1.00x** | **1.11x** |

**重みが 3.60 倍になっても KV は 1.11 倍にしかなりません。** 8B に至っては 4B と完全に同一です。

つまり大きいモデルへ差し替えると、**転送量をほぼ据え置いたまま Prefill の計算量だけが増えます。** 「計算」と「転送」のどちらが損益分岐を動かすのかを、ほぼ単一変数で切り分けられます。

### 1.1 環境

[04-results.md](04-results.md) と同一です。llama.cpp `b10679`、両機 `-c 16384 -np 1 -ngl 99 -fa on --cache-type-k q8_0 --cache-type-v q8_0 --no-context-shift`、転送は nginx + 8 並列 Range。

| モデル | サイズ | sha256 |
| --- | --- | --- |
| `unsloth/Qwen3-8B-GGUF` の `Qwen3-8B-Q4_K_M.gguf` | 5,027,784,512 B | `120307ba529eb2439d6c430d94104dabd578497bc7bfe7e322b5d9933b449bd4` |
| `unsloth/Qwen3-14B-GGUF` の `Qwen3-14B-Q4_K_M.gguf` | 9,001,753,984 B | `5eaa0870bd81ed3b58a630a271234cfa604e43ffb3a19cd68e54a80dd9d52a66` |

いずれも両機で sha256 の一致を確認済みです。

#### 14B は M1 16GB の実質上限です

重み 8.40 GB + KV 1.33 GB = 9.73 GB であり、計測中の M1 はメモリ空き 10% / swap 2.2 GB でした。

計測前に 1,024 トークンで単発のプローブを行い、18,514 ms (55.5 tok/s) を得ています。8B の実測 9,236 ms からパラメータ比で外挿した計算律速の見込み (約 16,000 ms) に対して +16% であり、**スワップが支配的ではないことを確認してから本計測に進みました。** プローブ中に swap 使用量は増えていません (2,236 → 2,229 MB)。

ただし 14B の M1 側の値には、8B・4B にはないメモリ制約の影響がいくらか含まれます。

### 1.2 KV サイズが同一であることの実地確認

両機の起動ログで、KV バッファが 4B のときと同じ値になることを確認しました。

```
# Qwen3-8B
llama_kv_cache:      CUDA0 KV buffer size =  1224.00 MiB     (4080)
llama_kv_cache:       MTL0 KV buffer size =  1224.00 MiB     (M1)

# Qwen3-14B
llama_kv_cache:      CUDA0 KV buffer size =  1360.00 MiB     (4080)
llama_kv_cache:       MTL0 KV buffer size =  1360.00 MiB     (M1)
```

8B は 16,384 トークン分で 1,224.00 MiB (76.5 KiB/token) であり、4B とビット単位で同一です。14B は 1,360.00 MiB (85.0 KiB/token) で、事前計算値と厳密に一致しました。

## 4. 損益分岐の変化

Wi-Fi 実測 (nginx / 8 並列) での速度比です。

| tokens | 4B | 8B | **14B** | 14B / 4B |
| --- | --- | --- | --- | --- |
| 1,027 | 3.77x | 7.36x | **12.49x** | 3.31x |
| 2,053 | 5.00x | 8.44x | **14.04x** | 2.81x |
| 4,105 | 5.76x | 9.34x | **13.75x** | 2.39x |
| 8,209 | 6.65x | 10.71x | **15.59x** | 2.34x |
| 16,012 | 8.94x | 12.66x | **19.69x** | 2.20x |

**16,012 トークンで M1 単体 412.0 秒に対し PD分離 20.9 秒。19.69 倍です。**

損益分岐は 3 モデルすべてで 1k トークンを下回っています。

## 5. 考察

### 5.1 仮説は支持されました

転送量をほぼ据え置いたまま計算量だけを増やした結果、**全プロンプト長・全モデルで速度比が単調に改善しました。**

PD分離の価値を決めるのは「Prefill をどれだけ肩代わりできるか」であり、モデルが大きいほどその差が大きくなります。

### 5.2 GQA のおかげで「計算だけが増える」

これは Qwen3 系が GQA を採用していることの直接的な帰結です。

| | 重み | KV | 16k の転送時間 | M1 の 16k Prefill |
| --- | --- | --- | --- | --- |
| 4B → 14B | **3.60x** | **1.11x** | **1.14x** | **2.95x** |

**コストは 3.60 倍、転送は 1.14 倍。** この乖離がそのまま PD分離の取り分になります。

MHA (KV ヘッド = アテンションヘッド) の古い世代のモデルであれば KV も重みに比例して増えるため、この効果は得られません。**最近の GQA 系モデルでは、大きいモデルほど PD分離が構造的に有利になります。**

### 5.3 改善幅は短いプロンプトほど大きい

14B / 4B の速度比の比は 1k で 3.31x、16k で 2.20x と、短いほど大きくなります。

短いプロンプトでは PD分離のオーバーヘッドに占める転送の比率が小さく、モデルサイズ増による Prefill 短縮がそのまま効きます。長いプロンプトでは転送が支配的になるため頭打ちになります。

**PD分離の上限は転送時間で決まります。** 16k・14B の内訳は Prefill 5.2 秒に対し転送 14.3 秒で、転送が 68% を占めます。

### 5.4 Decode は依然として改善しません

M1 の Decode は 14B の 16k で 3.2 tok/s です (4B は 7.0、8B は 5.5)。PD分離は TTFT のみを短縮するため、この値は変わりません。32 トークンの生成に 10 秒かかります。

**モデルを大きくすると TTFT の改善幅は広がりますが、生成そのものは遅くなります。** 14B・16k では TTFT 20.9 秒に対し 32 トークンの生成が 10 秒であり、**Decode 側の性能が実用上の制約であることに変わりはありません。**

### 5.5 実用上の含意

M1 のような Decode 専用機にとって、PD分離は「単体では現実的でないモデルサイズを実用圏に引き上げる」手段になります。

14B・16k の M1 単体は TTFT 412 秒であり実用になりません。PD分離では 20.9 秒です。ただし生成が 3.2 tok/s であるため、**長文を大量に生成する用途には向きません。長い文脈を読ませて短く答えさせる用途に適します。**
