# Claude Code のログで作った imatrix は量子化を良くするか(2026-11-imatrix-domain)

低ビットの量子化(IQ3_S など)は、imatrix(較正テキストを流したときの各入力の二乗平均)で丸め方を重み付けする。配布されている GGUF の imatrix は汎用の較正テキストで作られているので、実際の用途(Claude Code のエージェント作業)のテキストで作り直せば、その用途での劣化が減るかもしれない。ccshim に残っている Claude Code のリクエストから較正テキストを作り、unsloth 配布の imatrix、imatrix なしと、Q8_0 に対する KL ダイバージェンスで比べる。

本番の Qwen3.6-35B-A3B で試すには元になる Q8_0(約 37 GB)のダウンロードが要るため、手元にある Qwen3.5-9B の Q8_0 を元にした(ダウンロードは unsloth の imatrix 5 MB だけ)。

**完了(2026-11-22)。**

## 結論

**imatrix を使うかどうかは決定的だが、どのテキストで作るかはほとんど効かない。Claude Code 由来の imatrix と unsloth 配布の imatrix の差は KL で ±8% 以内で、向きもそろわなかった。**

| 評価テキスト       | 量子化 | imatrix なし | unsloth 配布 | Claude Code 由来 | 差(CC / unsloth) |
| ------------------ | ------ | ------------ | ------------ | ---------------- | ---------------- |
| Claude Code の会話 | IQ3_S  | 1.868        | 0.224        | 0.207            | −7.6%            |
|                    | Q4_K_M | 0.210        | 0.093        | 0.096            | +3.3%            |
| 日本語の技術文書   | IQ3_S  | 1.892        | 0.205        | 0.196            | −4.3%            |
|                    | Q4_K_M | 0.179        | 0.079        | 0.084            | +5.8%            |
| 英語の技術文書     | IQ3_S  | 1.573        | 0.071        | 0.070            | −1.2%            |
|                    | Q4_K_M | 0.038        | 0.018        | 0.017            | −3.2%            |

値は Q8_0 に対する KL の平均(nats)。各 6.5 万トークン(32 チャンク × 2,048)。KL の標準誤差は Claude Code と日本語で IQ3_S ±0.007、Q4_K_M ±0.005 前後、英語でその 4 分の 1 ほど。Claude Code 由来と unsloth の差は 6 組すべてで、2 つの標準誤差を合わせた値の 2 倍未満だった(同じトークン列での対応のある検定はしていない)。

- **imatrix なしの IQ3_S は壊れている。** KL 1.6〜1.9、1 位の一致率 48〜55%。どちらかの imatrix を使うと KL は 9〜22 分の 1 になり、一致率は 85〜90% に戻る。Q4_K_M でも imatrix で KL が半分以下になる
- **2 つの imatrix の重み付けはほぼ同じ向き。** テンソルごとの cos 類似度の中央値は 0.983。比べて、imatrix と一様な重み(imatrix なし)の cos は 0.08 前後で、重み付けそのものは一部の入力に強く偏っている。偏り方が同じなので、丸め方の選択もほとんど変わらない
- **違いが出るのは非線形の後の入力を受ける行列。** ffn_down(中央値 0.82、最小 0.40)、ssm_out(0.90)、attn_output(0.93)。入力側の正規化された残差を受ける行列(attn_qkv、ffn_up など)は 0.99 以上
- Claude Code 由来の imatrix で作り直す手間に見合う改善は無い。本番では配布の imatrix 付き量子化(unsloth の UD 系)をそのまま使ってよい

## なぜそうなるか

- **量子化は Σ_j a_j (w_j − q_j)² を小さくする丸め方を選ぶ。** a_j は入力 j の二乗平均(imatrix)。a の大きさの比が同じなら最適な丸め方は同じで、全体の大きさは結果に影響しない。2 つの imatrix の cos が 0.98 なら、選ばれる丸め方もほぼ同じになる
- **a は「どの入力チャネルが大きいか」でほぼ決まり、それはテキストの種類より、モデル自身の性質で決まる。** 残差の流れには常に大きな値を持つ少数のチャネルがあり(一様との cos 0.03〜0.4)、どのテキストを流してもそのチャネルが重み付けを支配する
- **非線形の後の入力は内容に依存する。** ffn_down の入力は SwiGLU の後、ssm_out は GDN の出力、attn_output は attention の出力で、どのニューロンや head が働くかがテキストで変わる。ここで領域差が出るが、全体の KL を動かすほどではなかった
- **IQ3_S で Claude Code 由来がやや良く、Q4_K_M でやや悪い理由は分けられていない。** 較正の量と文脈長が違う(unsloth は 11,264 トークン × 80 チャンク = 約 90 万トークン、こちらは 512 トークン × 100 チャンク = 5.1 万トークン)。量が少ないと統計がぶれ、文脈が短いと attention 出力の分布が変わる。どちらも領域の違いと区別できない

## 計測条件

- 元モデル: unsloth `Qwen3.5-9B-Q8_0.gguf`(密、GDN と attention の hybrid)。量子化は `llama quantize --allow-requantize [--imatrix X] q8_0.gguf out.gguf IQ3_S|Q4_K_M`。imatrix の有無でファイルサイズは同じ(IQ3_S 4.37 GB、Q4_K_M 5.63 GB)
- Claude Code のテキスト: ccshim の 3 つのログボリュームにある `/v1/messages` リクエスト(30 セッション)。セッションは最初のユーザー発話で識別し、各セッションで最も長いリクエストだけを使った。imatrix と perplexity は特殊トークンを解釈しないので、チャットテンプレートは使わず、system・ツール定義・会話(本文、thinking、tool_use の入力、tool_result)を順に並べた素のテキストにした
- 較正と評価の分け方: セッションキーのハッシュで 21 セッションを較正、9 セッションを評価に分けた。system とツール定義(約 22 万文字、全セッションでほぼ同じ)は較正側に 1 回だけ入れ、評価側からは外した。較正テキストは 2,000 文字以下の断片にして固定シードで並べ替えた(imatrix は先頭から決まった数のチャンクしか読まないので、そのままだと system とツール定義ばかりで較正してしまう)
- imatrix: `llama-imatrix -c 512 --chunks 100 -t 6`(CPU で 37 分)。unsloth の imatrix は `imatrix_unsloth.gguf_file`(データセット名 `unsloth_calibration_Qwen3.5-9B.txt`)
- 評価テキスト: Claude Code の評価 9 セッション(29 万文字)、このリポジトリの実験 README(日本語の技術文書、28 万文字)、llama.cpp の `docs/` 以下(英語、57 万文字)
- KL: `llama perplexity -c 2048 --chunks 32 -ngl 99` で Q8_0 の logits を保存し(`--kl-divergence-base`)、各量子化で `--kl-divergence`。Q8_0 自体の PPL は Claude Code 4.11、日本語 6.15、英語 4.01
- imatrix の比較: imatrix の GGUF からテンソルごとに in_sum2 / counts を出し、cos 類似度を取った(`scripts/imatrix_cos.py`)

## 結果

### その他の指標(Claude Code の会話)

| 量子化 | imatrix          | 1 位の一致率 | KL の 99% 点 | PPL   |
| ------ | ---------------- | ------------ | ------------ | ----- |
| IQ3_S  | なし             | 50.6%        | 11.86        | 15.61 |
| IQ3_S  | unsloth 配布     | 87.9%        | 5.86         | 4.32  |
| IQ3_S  | Claude Code 由来 | 88.4%        | 5.41         | 4.14  |
| Q4_K_M | なし             | 90.4%        | 6.69         | 3.72  |
| Q4_K_M | unsloth 配布     | 93.6%        | 1.89         | 4.04  |
| Q4_K_M | Claude Code 由来 | 93.4%        | 2.06         | 4.02  |

Q4_K_M の imatrix なしは PPL が Q8_0(4.11)より低いが、KL は 2 倍で一致率も低い。PPL だけで量子化を比べると逆の結論になる。全指標は `results/kld.csv`。

### imatrix の重み付けの類似度(cos、テンソル種別ごとの中央値)

| テンソル                                    | CC vs unsloth | CC vs 一様 | unsloth vs 一様 |
| ------------------------------------------- | ------------- | ---------- | --------------- |
| attn_qkv / attn_gate / ssm_alpha / ssm_beta | 0.9993        | 0.029      | 0.025           |
| attn_q / attn_k / attn_v                    | 0.9958        | 0.046      | 0.034           |
| ffn_up / ffn_gate                           | 0.9900        | 0.091      | 0.074           |
| attn_output                                 | 0.9282        | 0.356      | 0.412           |
| ssm_out                                     | 0.8973        | 0.198      | 0.199           |
| ffn_down                                    | 0.8236        | 0.336      | 0.400           |

同じ入力を共有するテンソル(attn_qkv と attn_gate など)は同じ値になる。最も違うのは層 0 の ffn_down(0.40)と層 24 の ssm_out(0.45)。全テンソルは `results/imatrix-cos-*.json`。

## 落とし穴

| 罠                                                     | 症状                                                                              | 対処                                                                 |
| ------------------------------------------------------ | --------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| llama-swap のイメージに imatrix ツールが無い           | `/app/llama` のサブコマンドは quantize と perplexity まで                         | 同じコミットのソースを LAN 経由で GPU 機に送り、CPU 版だけビルドした |
| imatrix は較正テキストの先頭から決まった数しか読まない | 先頭に置いた system とツール定義(約 5.5 万トークン)だけで較正しかけた             | 断片に分けて固定シードで並べ替えた                                   |
| imatrix の途中保存                                     | 10 チャンクごとに出力ファイルが書かれるので、ファイルの有無では完了を判定できない | プロセスの終了を待つ                                                 |

| PPL は量子化の比較に向かない                           | imatrix なしの Q4_K_M が Q8_0 より PPL が低い                                     | KL と 1 位の一致率で比べる                                           |
