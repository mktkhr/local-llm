# PD分離 PoC — KV キャッシュ量子化による転送量の削減

PD分離のオーバーヘッドの大部分は KV キャッシュの転送です ([04-results.md](04-results.md) §5.5、[05-model-scaling.md](05-model-scaling.md) §5.3)。転送量は KV 量子化に比例するため、`q8_0` から `q4_0` へ落として効果を実測しました。

- 実施日: 2026-08-30
- 対象: Qwen3-4B-Instruct-2507 / Qwen3-14B (いずれも重みは Q4_K_M)
- 結果: **転送量が 53% に減り、16k の速度比は 4B で 8.94x → 13.76x、14B で 19.69x → 22.55x**

## 1. 実験設計

`--cache-type-k` / `--cache-type-v` を `q8_0` から `q4_0` へ変更し、それ以外は [05-model-scaling.md](05-model-scaling.md) と同一の条件で A / B / C を測り直しました。

**KV の型は両機で一致している必要があります。** 不一致の場合 restore は `mismatched key type` で失敗します ([01-research.md](01-research.md) §3)。`q4_0` の V キャッシュは Flash Attention が必須ですが、本 PoC は当初から `-fa on` を明示しているため追加の対応は不要でした。

### 1.1 KV サイズは設計どおり 53% になりました

起動ログの `KV buffer size` (16,384 トークン分) です。

| モデル | q8_0 | q4_0 | 比 |
| --- | --- | --- | --- |
| Qwen3-4B | 1,224.00 MiB | **648.00 MiB** | 0.529 |
| Qwen3-14B | 1,360.00 MiB | **720.00 MiB** | 0.529 |

1 トークンあたりでは 76.5 KiB → 40.5 KiB (4B)、85.0 KiB → 45.0 KiB (14B) です。`q4_0` は 32 要素ごとに 18 バイト、`q8_0` は 34 バイトを使うため、比は 18/34 = 0.529 になります。事前計算と厳密に一致しました。

## 2. 転送時間

16,012 トークンでの実測です。

| モデル | KV 型 | KV サイズ | 転送 | 実効 |
| --- | --- | --- | --- | --- |
| 4B | q8_0 | 1,196.5 MiB | 12,512 ms | 95.6 MiB/s |
| 4B | **q4_0** | **633.5 MiB** | **7,467 ms** | 84.8 MiB/s |
| 14B | q8_0 | 1,329.4 MiB | 14,294 ms | 93.0 MiB/s |
| 14B | **q4_0** | **703.9 MiB** | **8,417 ms** | 83.6 MiB/s |

転送時間は 4B で 60%、14B で 59% になりました。サイズ比 (0.529) ほど縮んでいないのは、実効スループットが 95.6 → 84.8 MiB/s と落ちているためです。転送が短くなるほど TCP のスロースタートの比率が上がることが原因と考えられます。

## 3. Prefill / Decode への影響

### 3.1 Prefill 速度はほとんど変わりません

| モデル | tokens | q8_0 | q4_0 |
| --- | --- | --- | --- |
| 4B (M1) | 16,012 | 139,791 ms | 138,461 ms |
| 4B (4080) | 16,012 | 1,943 ms | 1,941 ms |
| 14B (4080) | 16,012 | 5,197 ms | 5,108 ms |

**Prefill は KV 量子化の影響をほとんど受けません。** 差は測定のばらつきの範囲です。

### 3.2 Decode はむしろ速くなります

| モデル | tokens | q8_0 | q4_0 |
| --- | --- | --- | --- |
| 4B (M1) | 1,027 | 19.0 tok/s | 19.0 tok/s |
| 4B (M1) | 16,012 | 7.0 tok/s | **7.9 tok/s** |
| 14B (M1) | 16,012 | 3.2 tok/s | **3.9 tok/s** |

長コンテキストでは Decode が KV の読み出し帯域に律速されるため、KV が小さいほど速くなります。16k で 4B は +13%、14B は +22% です。

**KV 量子化は転送量と Decode 速度の両方に効きます。**

### 3.3 14B では M1 のメモリ圧迫も緩みます

14B は M1 16GB の実質上限です ([05-model-scaling.md](05-model-scaling.md) §1.1)。`q4_0` にすると KV が 640 MiB 減るため、計測中のメモリ空きが 10% から 17% へ改善しました。

その結果、**14B の M1 単体 Prefill は 16k で 412.0 秒から 366.2 秒へ短縮しています。** これは KV 量子化そのものの効果ではなくメモリ圧迫の緩和によるものです。

したがって **14B の q8_0 と q4_0 の速度比を直接比較することはできません。** 分母 (M1 単体) の条件が異なります。4B にはこの制約がないため、4B の比較のほうが KV 量子化の純粋な効果を表します。

## 4. 損益分岐

Wi-Fi 実測 (nginx / 8 並列) での速度比です。

### 4.1 Qwen3-4B (メモリ制約なし。KV 量子化の純粋な効果)

| tokens | q8_0 | **q4_0** | 改善 |
| --- | --- | --- | --- |
| 1,027 | 3.77x | **7.48x** | +98% |
| 2,053 | 5.00x | **8.57x** | +71% |
| 4,105 | 5.76x | **8.27x** | +44% |
| 8,209 | 6.65x | **11.14x** | +68% |
| 16,012 | 8.94x | **13.76x** | +54% |

### 4.2 Qwen3-14B (§3.3 のとおり分母の条件が異なります)

| tokens | q8_0 | **q4_0** |
| --- | --- | --- |
| 1,027 | 12.49x | **13.68x** |
| 2,053 | 14.04x | **11.70x** |
| 4,105 | 13.75x | **13.66x** |
| 8,209 | 15.59x | **19.92x** |
| 16,012 | 19.69x | **22.55x** |

**16,012 トークンで M1 単体 366.2 秒に対し PD分離 16.2 秒です。**

2,053 トークンで q4_0 が下回っているのは、その試行の転送実効が 39.9 MiB/s と外れ値だったためです。Wi-Fi の変動の範囲です。

## 5. 観測された異常

Qwen3-14B の `q4_0` で、KV save の所要時間が不自然に長くなりました。

| モデル | KV 型 | tokens | KV サイズ | save 時間 | 実効 |
| --- | --- | --- | --- | --- | --- |
| 4B | q4_0 | 16,012 | 633.5 MiB | 294 ms | 2,155 MiB/s |
| 14B | q8_0 | 16,012 | 1,329.4 MiB | 640 ms | 2,077 MiB/s |
| **14B** | **q4_0** | **16,012** | **703.9 MiB** | **2,142 ms** | **329 MiB/s** |

他の 3 条件が 2,000 MiB/s 前後で揃っているのに対し、14B の `q4_0` だけが 6 倍以上遅くなっています。**原因は特定できていません。** 再現確認も行っていません。

転送時間 (8,417 ms) に対して save は 2,142 ms であり、結論を左右する規模ではありませんが、追試の際に確認すべき点として記録しておきます。

## 6. 品質への影響は未評価です

**本 PoC では `q4_0` による出力品質の劣化を測定していません。** PD分離の速度特性の確認が目的であり、生成テキストが破綻していないことの目視確認にとどめています。

品質を評価する場合は、本リポジトリの [docs/06-evaluation.md](../06-evaluation.md) の方法論と [scripts/bench/](../../scripts/bench/) の needle 手法が使えます。長コンテキストでの情報抽出能力は KV 量子化の影響を受けやすいため、`q4_0` を実用に供する前には測定が必要です。

## 7. まとめ

| 観点 | q8_0 → q4_0 の効果 |
| --- | --- |
| KV サイズ | **53%** に減少 |
| 転送時間 | **59〜60%** に減少 |
| Prefill 速度 | ほぼ変化なし |
| Decode 速度 (16k) | **+13〜22%** 向上 |
| M1 のメモリ圧迫 | 緩和 (14B で空き 10% → 17%) |
| 速度比 (4B / 16k) | 8.94x → **13.76x** |
| 品質 | [07-kv-quality.md](07-kv-quality.md) で測定。**検出可能な劣化なし** (ただし検出力に限界あり) |

**転送が支配的である以上、KV 量子化は PD分離にとって最も費用対効果の高い施策です。** 品質については [07-kv-quality.md](07-kv-quality.md) で測定し、f16 との差を検出できませんでした。

## 8. 途中で見つけた不具合

`scripts/pd/baseline.py` が全試行の完了後にまとめて結果を書き出す実装だったため、14B の掃引がタイムアウトした際に取得済みの結果もすべて失われました。**1 件ごとに追記するよう修正済みです。** M1 の 16k Prefill は数分かかるため、まとめ書きは危険でした。
