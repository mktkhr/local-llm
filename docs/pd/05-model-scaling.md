# PD分離 PoC — モデルサイズによる損益分岐の変化

「PD分離の優位はモデルが大きいほど広がる」という仮説を、**転送コストを固定したまま計算コストだけを変える**設計で検証した記録です。

- 実施日: 2026-08-30
- 結果: **仮説どおり。全プロンプト長で速度比が改善**

## 1. 実験設計

Qwen3-8B は Qwen3-4B-Instruct-2507 と **KV キャッシュのサイズが完全に一致します。**

| | Qwen3-4B-Instruct-2507 | Qwen3-8B |
| --- | --- | --- |
| `n_layer` | 36 | 36 |
| KV ヘッド数 | 8 | 8 |
| `head_dim` | 128 | 128 |
| `n_embd_k_gqa` | 1024 | 1024 |
| **KV (q8_0)** | **76.5 KiB/token** | **76.5 KiB/token** |
| 重み (Q4_K_M) | 2.50 GB | 5.03 GB |

つまり **8B へ差し替えると、転送量は 1 バイトも変わらないまま、Prefill の計算量だけが増えます。** 「計算」と「転送」のどちらが損益分岐を動かすのかを、単一変数で切り分けられます。

### 1.1 環境

[04-results.md](04-results.md) と同一です。llama.cpp `b10679`、両機 `-c 16384 -np 1 -ngl 99 -fa on --cache-type-k q8_0 --cache-type-v q8_0 --no-context-shift`、転送は nginx + 8 並列 Range。

| | 値 |
| --- | --- |
| モデル | `unsloth/Qwen3-8B-GGUF` の `Qwen3-8B-Q4_K_M.gguf` |
| サイズ | 5,027,784,512 B |
| sha256 | `120307ba529eb2439d6c430d94104dabd578497bc7bfe7e322b5d9933b449bd4` |

両機で sha256 の一致を確認済みです。

### 1.2 KV サイズが同一であることの実地確認

両機の起動ログで、KV バッファが 4B のときと同じ値になることを確認しました。

```
llama_kv_cache:      CUDA0 KV buffer size =  1224.00 MiB     (4080)
llama_kv_cache:       MTL0 KV buffer size =  1224.00 MiB     (M1)
```

16,384 トークン分で 1,224.00 MiB、すなわち 76.5 KiB/token です。4B とビット単位で同一です。

## 5. 考察

### 5.1 仮説は支持されました

転送量を 1 バイトも変えずに計算量だけを増やした結果、**全プロンプト長で速度比が改善しました。** PD分離の価値を決めるのは「Prefill をどれだけ肩代わりできるか」であり、モデルが大きいほどその差が大きくなります。

### 5.2 改善幅は短いプロンプトほど大きい

改善率は 1k で +95%、16k で +42% と、短いほど大きくなります。

短いプロンプトでは PD分離のオーバーヘッドに占める転送の比率が小さく、モデルサイズ増による Prefill 短縮がそのまま効きます。長いプロンプトでは転送が支配的になるため、Prefill をいくら速くしても頭打ちになります。

**PD分離の上限は転送時間で決まります。** 16k・8B の内訳は Prefill 2.8 秒に対し転送 12.3 秒で、転送が 76% を占めます。

### 5.3 GQA モデルでは大きいモデルほど PD分離が効きます

Qwen3 系は 4B から 8B までアテンション構成 (層数 / KV ヘッド数 / head_dim) が同一で、**KV サイズはモデルサイズに比例しません。** 14B でも 40 層 / KV ヘッド 8 / head_dim 128 で 85.0 KiB/token であり、4B の 1.11 倍にしかなりません。

一方 Prefill の計算量はパラメータ数に比例して増えます。**GQA を採用した最近のモデル系列では、大きいモデルほど「計算は重く、転送は変わらない」ため、PD分離が構造的に有利になります。**

### 5.4 Decode は依然として改善しません

M1 の Decode は 8B の 16k で 5.5 tok/s です (4B は 7.0 tok/s)。PD分離は TTFT のみを短縮するため、この値は変わりません。32 トークンの生成に 5.8 秒かかります。

**モデルを大きくすると TTFT の改善幅は広がりますが、生成そのものは遅くなります。** Decode 側の性能が実用上の制約であることに変わりはありません。

## 6. 次に確認すべきこと

- **Qwen3-14B** (85.0 KiB/token、Q4_K_M 8.40 GB)。M1 16GB では重み 8.40 GB + KV 1.33 GB = 9.73 GB でぎりぎり載る見込みです。§5.3 の「KV はモデルサイズに比例しない」がさらに強く出るはずです
- KV 量子化 q4_0 での転送半減。§5.2 のとおり長文では転送が 76% を占めるため、ここが最も効きます
