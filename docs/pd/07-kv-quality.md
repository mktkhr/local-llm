# PD分離 PoC — KV 量子化が長文の情報抽出能力に与える影響

[06-kv-quantization.md](06-kv-quantization.md) で `q4_0` が転送量を大きく減らすことを確認しましたが、品質への影響は未評価のままでした。Needle In A Haystack で測定した記録です。

- 実施日: 2026-08-30
- モデル: Qwen3-4B-Instruct-2507 Q4_K_M
- 結果: **`q4_0` に検出可能な劣化はありませんでした。ただし本試験の検出力は高くありません**

## 1. 結論

| 比較 | 正答率 | Fisher の正確確率検定 |
| --- | --- | --- |
| f16 (基準) | 19/27 | — |
| q8_0 | 23/27 | p = 0.327 |
| **q4_0** | **19/27** | **p = 1.000** |

`q4_0` は基準の f16 と同点でした。

**`q8_0` が f16 を上回っている点に注意してください。** KV を量子化して f16 より良くなることは原理上ありえないため、**この差はすべて試行間のばらつきです。** 同じ理由で `q4_0` の「劣化なし」も、劣化が無いことの証明ではなく「この試験では検出できなかった」という意味です (§5)。

## 2. 方法

### 2.1 データ

[scripts/bench/data/needle/generate.py](../../scripts/bench/data/needle/generate.py) をそのまま使いました。ランタイムに依存しないため、Ollama 向けの既存資産を流用できます。

決定論的な日本語フィラーの指定位置に「秘密の数字は NNNNNN です」を埋め込み、末尾でその数字を問います。**採点は応答に needle_id が含まれるかの 2 値であり、主観が入りません。**

| 軸 | 値 |
| --- | --- |
| 文脈長 | 4,144 / 8,276 / 16,219 トークン |
| needle 位置 | 10% / 50% / 90% |
| フィラーのシード | 42 / 7 / 123 |

3 × 3 × 3 = **27 試行 / KV 型**です。

### 2.2 実行

llama-server 用のランナーを [scripts/pd/needle_llamacpp.py](../../scripts/pd/needle_llamacpp.py) として新規に作成しました (既存の `run_needle.py` は Ollama 依存のため)。

- `temperature 0.0` / `seed 1234` の貪欲デコードに固定
- 試行ごとに `/slots/0?action=erase` で prompt cache を破棄。**残っていると別の KV 型のキャッシュを再利用してしまい、比較が壊れます**
- 主掃引は 4080 (CUDA) 上で実施。M1 では 16k の Prefill だけで 140 秒かかり、81 試行が現実的でないため

### 2.3 途中で修正した測定上の欠陥

初回は `n_predict=64` で測り、f16 の基準が 6/9 にとどまりました。失敗した応答を確認すると、**モデルが前置きを生成している途中で打ち切られていました。** 品質ではなく生成長の不足による FAIL です。

`n_predict=256` に変更したところ同一条件が 8/9 になりました。**この設定が誤っていると KV 量子化の影響を過大評価します。**

## 3. 結果

### 3.1 全体

| KV 型 | 4k | 8k | 16k | pos 0.1 | pos 0.5 | pos 0.9 | 全体 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| f16 | 5/9 | 8/9 | 6/9 | 5/9 | 7/9 | 7/9 | **19/27** |
| q8_0 | 8/9 | 8/9 | 7/9 | 7/9 | 8/9 | 8/9 | **23/27** |
| q4_0 | 4/9 | 9/9 | 6/9 | 6/9 | 8/9 | 5/9 | **19/27** |

文脈長・needle 位置のいずれでも、KV 型と正答率の間に一貫した傾向はありません。`q4_0` は 8k で 9/9 と最も良く、4k で 4/9 と最も悪くなっています。**KV 量子化の影響ではなく、境界事例のばらつきとして説明できます。**

### 3.2 PD分離の実経路 (CUDA → Metal)

`q4_0` について、4080 で Prefill して M1 へ転送・restore し、M1 で Decode する実経路でも測りました (シード 42 の 9 試行)。

| ケース | CUDA 単体 | PD (cuda→metal) | 一致 |
| --- | --- | --- | --- |
| 4k / pos 0.1 | FAIL | FAIL | ○ |
| 4k / pos 0.5 | OK | OK | ○ |
| 4k / pos 0.9 | FAIL | OK | × |
| 8k / pos 0.1 | OK | OK | ○ |
| 8k / pos 0.5 | OK | OK | ○ |
| 8k / pos 0.9 | OK | OK | ○ |
| 16k / pos 0.1 | OK | FAIL | × |
| 16k / pos 0.5 | OK | OK | ○ |
| 16k / pos 0.9 | OK | OK | ○ |
| **合計** | **7/9** | **7/9** | **7/9 一致** |

**正答数は同じでした。** 不一致 2 件は互いに逆方向 (片方だけ OK) であり、系統的な劣化ではありません。

全試行で `prompt_n = 1` であり、**再 Prefill が起きていないことも確認しています。** Prefill 時間は 78〜134 ms で、M1 単体なら 16k で 140 秒かかる処理です。

## 4. 転送量と品質のまとめ

| KV 型 | 16k の KV | 16k の転送 | 正答率 |
| --- | --- | --- | --- |
| f16 | 2,304 MiB | (未計測) | 19/27 |
| q8_0 | 1,224 MiB | 12,512 ms | 23/27 |
| **q4_0** | **648 MiB** | **7,467 ms** | **19/27** |

**転送量を f16 の 28% に落としても、この試験の範囲では品質差を検出できませんでした。**

## 5. 本試験の限界

以下を踏まえて解釈してください。

- **検出力が不足しています。** 27 試行では、`q8_0` が f16 を 4 件上回るという原理的にありえない結果が出る程度のばらつきがあります。真の差が数ポイント程度なら検出できません
- **モデル自体の正答率が低すぎます。** 基準の f16 が 19/27 (70%) であり、上下双方に余地がある状態です。f16 で 100% に近いモデルのほうが劣化を検出しやすくなります
- **単一モデルのみです。** Qwen3-4B での結果であり、他のモデル・他のパラメータ数へは外挿できません
- **needle 課題のみです。** 長文からの単一事実の抽出しか測っていません。要約・推論・コード生成での劣化は測っていません

**「`q4_0` は安全」ではなく「この条件では劣化を検出できなかった」が正確な結論です。**

## 6. 実用上の判断

転送量が 53% になり Decode が 13〜22% 速くなる ([06-kv-quantization.md](06-kv-quantization.md)) 一方、品質差は検出されませんでした。**PD分離の用途では `q4_0` を選ぶ合理性があります。**

ただし §5 のとおり検出力に限界があるため、品質が重要な用途では以下を推奨します。

- 対象モデルと実タスクで [docs/06-evaluation.md](../06-evaluation.md) の方法論に沿って測り直す
- 迷う場合は `q8_0` を選ぶ。転送量は f16 の 53% に減り、品質面の懸念は `q4_0` より小さくなります
